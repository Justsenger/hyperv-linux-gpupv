# 工程决策
- 采用单卡单包，使用 Hyper-V 实例路径匹配完整 PCI 设备实例，再从已绑定的发布 INF 反查驱动包。名称相同的设备仍可区分。
- Windows 侧打包和部署不修改任何 VM。测试资源使用唯一名称并持有创建结果中的 VM ID。
- 运行库缺失时先失败，避免导出看似完整的空包。运行库可以来自已有目录或经校验的本地缓存。
- 内核接口用 Kbuild 实际编译，基线探针必须先成功。编译矩阵和普通用户 GPU 功能证据分别记录。
- 在离线来宾中使用已安装的精确版本头文件。保留原有包管理与内核策略。
- 仅发布本项目源码工具，厂商二进制通过本机提取生成。P1 优先在单进程作用域选择 Mesa 后端。
- 此次查询的微软主分支包含 6.6 和 6.18，未列出 linux-msft-wsl-6.12.y。对 Debian 6.12 的支持依据目标头文件实编记录。分支列表保存在 artifacts/reports/wsl-branches.txt。
- NVIDIA 本机显示 INF 把 libcuda_loader.so 映射为 libcuda.so.1 等外部文件名。宿主按 INF 中 DestinationDirs 指向 11,lxss\lib 的 CopyFiles 段生成这些别名，并保留原 DriverStore 包。Intel 本机 INF 没有该映射，其包中亦未检出 .so 文件。
- 计算所需的长期页固定接口需在目标头文件中真实存在。Ubuntu 20.04 的 GA 内核缺少所需接口时报告编译阻断；HWE 内核单独测试。
- Debian 11 安全仓库若返回 404，保留实时源失败日志，同时测试官方基础仓库和指定时刻的签名快照。仅历史快照的有效期检查按快照语义配置，保留 Release 签名与软件包散列核验。
- 真实来宾探测在同一时刻顺序绑定单卡。独立保留 VMBus 枚举、启动、SSH 和工作负载的证据，以区分虚拟设备呈现与加速成功。

无 WSL 部署采用显式下载、固定提交、逐文件 SHA-256、ELF 机器类型校验和本地缓存。运行时及 DriverStore 设备包仅保存在本机，首次获取后的打包、ISO 与来宾安装均可离线运行。

Ubuntu 的云镜像可以同时枚举 VMBus 并缺少虚拟 PCI 控制器。Ubuntu 24.04 的实际测试中，安装与当前内核匹配的 linux-modules-extra 并加载 pci_hyperv 后，PCI 层出现 1414:008e，RTX 2060 的 CUDA、NVENC 与 CUVID 才得到正例。测试运行前补齐依赖，离线来宾部署器继续使用本地文件。

Ubuntu 24.04 的编解码测试触发了 GPU 栅栏数组的内核 FORTIFY 告警。随包驱动已把该变长数组从单元素占位声明改为柔性数组，按成员偏移、栅栏数与句柄数计算消息长度，保留原来的对象数上限。微软 linux-msft-wsl-6.18.y 的同一协议结构也使用柔性数组。历史二进制的运行证据保留在原试验目录中。

测试用的 Ubuntu 24.04 FFmpeg 与其用户态依赖仅保存在 .tools。在其他基座的系统 FFmpeg 缺失 NVENC 或 CUVID 时，验收脚本可用该隔离工具发起真实硬件编解码；记录保留原生能力检查、工具包摘要和真实帧。该工具包不进入交付的设备包或源码包。
